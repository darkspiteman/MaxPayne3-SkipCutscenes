### Защита исполняемого файла

- Точка входа находится в секции `.rkstr` (657 байт). Заглушка загружает `MTLX.dll` и через неё
  расшифровывает код, затем вызывает инициализаторы и переходит на настоящую точку входа.
- На диске **зашифрованы первые ~1000 КиБ секции `.text`** (VA `0x00401000..0x004FB000`, энтропия 7.96);
  остальные ~12.9 МиБ кода — обычный открытый код (энтропия ~4.75).
- В зашифрованной части лежит почти всё, что нужно моду: `CutSceneManager`, его проверка пропуска, видеоплеер,
  главный цикл. Поэтому **статически по файлу эти сигнатуры проверить нельзя** — только в памяти запущенной игры.
- Мод защиту **не трогает**: он ждёт, пока игра сама расшифрует код (появится окно игры), и только потом ищет
  сигнатуры. `MTLX.dll`, Steam и Rockstar Launcher не изменяются.

Проверка сигнатур по файлу (`research/tools/scan_patterns.py`):

| Сигнатура | В файле | Где |
|---|---|---|
| поиск нативной функции (`53 8B 59 04 85 DB`) | 1 совпадение | `0x010FD050`, открытая часть |
| ссылка на таблицу нативных функций | 1 совпадение | `0x010FED22`, вызов ведёт в `0x010FD050` ✔ |
| видеоплеер (`SET_TRANSITION_MOVIE_SKIPPABLE`) | 1 совпадение | `0x008758C0`, объект `0x0186C128` |
| вызов игрового цикла | 0 | зашифрованная часть |
| указатель на `CutSceneManager` | 0 | зашифрованная часть |
| сброс флага пропуска (×2) | 0 | зашифрованная часть |
| проверка пропуска кат-сцены | 0 | зашифрованная часть |

Дополнительно подтверждено по открытой части:

- тело `CUTSCENE_ENABLE_SKIP` (`0x00872630`): `call GetManager; mov cl,[esp+4]; mov [eax+39F8h],cl; ret` —
  смещение флага `0x39F8` совпадает с используемым в моде;
- поиск нативной функции возвращает указатель на структуру `{int index; void (*fn)(context*)}`
  (`mov eax,[ecx+edx*8+4]`), `ret 4` — соглашение `thiscall(hash)`.

## 3. Существующие решения

### 3.1. «Cutscene Skipper» (speedrun.com `y70xu`, Steam-руководство `1437714794`, gamepressure «v0.2», автор l0m)

- Страницы speedrun.com и Steam отдали 403/429, описание получено из поисковой выдачи и с gamepressure:
  «ScriptHook-плагин, пропускающий кат-сцены сразу, не дожидаясь фиктивного времени загрузки»; известная
  проблема v0.2 — чёрный экран после пропуска сцены перед боссом Беккером и смерти. Исходников нет.
- Установленный у вас `SkipCutscenes.asi` — плагин того же типа (собран 04.02.2018, одновременно с
  ASI-загрузчиком Unknown Modder; тот ли это файл, что на speedrun.com, по содержимому установить нельзя).
  Он импортирует из `ScriptHook.dll` функции `scriptRegister`, `nativeInit`, `nativePush32`, `nativeCall`,
  `keyboardHandlerRegister`, `scriptWait`, то есть работает как скриптовый поток ScriptHook и вызывает нативные
  функции игры по клавише.
- Предположение (файл не дизассемблировался): пропуск делается немедленно, без ожидания подгрузки уровня и без
  «хвоста» сцены для скриптов — это согласуется с описанными вылетами и чёрным экраном.
- Требует **Max Payne 3 Script Hook** (alloc8or, закрытый бинарник, v1.0.21.0). Официально поддерживаются
  только 1.0.0.114 / 1.0.0.216 / 1.0.0.255; **1.0.0.276 в списке нет**.
- SDK плагинов открыт: <https://github.com/alloc8or/mp3-plugin-sdk>, но сам ScriptHook закрыт.

Вывод: путь «ScriptHook-плагин» отвергнут — закрытая зависимость без поддержки текущей версии игры и подход,
который и даёт вылеты.

### 3.2. MaxPayne3.FusionFix (ThirteenAG, GPL-3.0, исходники открыты)

<https://github.com/ThirteenAG/MaxPayne3.FusionFix>, модуль `source/cutsceneskip.ixx`
(копия для изучения — `research/fusionfix-src/`). Опция `CutsceneSkip`. Механизм:

1. Хук обработчика нативной функции `CUTSCENE_ENABLE_SKIP`: флаг игры всегда держится «можно пропускать», а то,
   что просил скрипт, запоминается отдельно.
2. Кат-сцены, которые скрипт разрешает пропускать, — без изменений (штатный пропуск).
3. Кат-сцены, которые скрипт блокирует (обычно они маскируют подгрузку следующего участка): по кнопке пропуска
   сцена **перематывается на 3 секунды до конца** (`SeekFrame`), звук синхронизируется, через 3 кадра и
   перед самым концом вызывается `LOAD_ALL_OBJECTS_NOW`. Сцена заканчивается штатно, скрипты идут своим путём.
4. Transition-ролики (Bink): флаг «можно пропустить» выставляется, когда `GET_NUMBER_OF_STREAMING_REQUESTS == 0`.

Это самый надёжный из найденных подходов: скрипты получают свой «хвост» сцены и ничего не ломается в
последовательности уровня. Он взят за основу.

Важно: **FusionFix уже содержит эту функцию**. Если нужен просто пропуск штатной кнопкой — можно поставить
FusionFix. Данный мод — отдельная минимальная реализация того же механизма без зависимостей, с клавишей Space,
строгой проверкой сигнатур и логом. Одновременно с FusionFix использовать нельзя (мод это определяет и
отключается).

## 4. Ролики, связанные с загрузкой мира

Bink-файлы лежат открыто в `common\movies\` (88 файлов, 8.25 ГБ):

- **Transition-ролики между главами/участками** (во время них идёт подгрузка уровня; именно на них игра пишет
  «STILL LOADING»): `s_air`, `s_beach`, `s_boat`, `s_busdep`, `s_cemet`, `s_club`, `s_clubride`, `s_fashion`,
  `s_fav0`, `s_fav1`, `s_fav2`, `s_fire`, `s_hotel`, `s_marina`, `s_nyc`, `s_nyc2`, `s_office`, `s_pana`,
  `s_police`, `s_stad` (`.bik`, 200–900 МБ каждый). В игре это «transition movie» (слот 0 видеоплеера),
  нативные функции `IS_TRANSITION_MOVIE_PLAYING`, `SET_TRANSITION_MOVIE_SKIPPABLE`.
- **Заставки при запуске**: `fe_intro.bik`, `mp3_logo_bink_pt02.bik` — к загрузке мира не относятся, модом не
  затрагиваются.
- **Внутриигровые экраны**: `tv_*.bik` (телевизоры), `death_screen_*.bik`, `03_04_stad_cam*.bik` и т.п. — это
  «script movies», мод их не трогает.

Кроме Bink, загрузку маскируют **обычные кат-сцены на движке**: скрипт вызывает `CUTSCENE_ENABLE_SKIP(FALSE)`,
пока следующий участок не подгружен. Это второй вид «заблокированных» роликов.

## 5. Выбранный метод

ASI-плагин (32-битная DLL, C++17, без сторонних библиотек), загружаемый ASI-загрузчиком через `dinput8.dll`.

- Поиск кода по сигнатурам в памяти после расшифровки, проверка числа совпадений и каждого адреса;
  при любом несовпадении соответствующая функция мода отключается, игра остаётся нетронутой.
- Патчи ставятся при приостановленных остальных потоках, с проверкой, что байты не изменились.
- Хуки: вызов игрового цикла (покадровый обработчик), вход в проверку пропуска кат-сцены, вызов «кнопка
  пропуска нажата» (добавляется Space), два места сброса флага пропуска, обработчик `CUTSCENE_ENABLE_SKIP`.
- Файлы игры на диске не изменяются вообще. Удаление — удалить файлы мода.

## 6. Что осталось непроверенным на этом этапе

Сигнатуры и смещения из зашифрованной части кода (игровой цикл, `CutSceneManager`, проверка пропуска, сбросы
флага) известны по исходникам FusionFix и **не могут быть подтверждены без запуска игры**. Первая же загрузка
мода в игре запишет в `MP3SkipCutscenes.log`, что найдено. См. `docs/TESTING.md`.
